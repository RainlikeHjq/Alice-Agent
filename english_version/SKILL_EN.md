# longterm-mem

This skill describes how an AI Agent converts short-term memory (conversation history) into long-term memory (memory documents), and maintains the five-level long-term memory pyramid in the `mems/` directory.

## Primary Memory Content

1. **User Profile:**
   - Basic information, interests, professional background, research direction, etc.
   - Preferences, habits, behavioral patterns, etc.
2. **Schedule & Events:**
   - Schedule arrangements, including meetings, tasks, reminders, etc.
   - Events that occurred, conversations held, topics discussed, etc.

**Core principle for deciding what to remember:** After starting a new conversation session, the user's interactive experience should still feel continuous.

## High-Level Memory Abstraction

As the memory level increases, the amount of content to be remembered also grows significantly. Therefore, the abstraction capability of long-term memory needs to strengthen as the level rises. Specifically:

- The higher the memory level, the more it should adopt a **summarizing** approach rather than recording items one by one.
- In high-level memories, unimportant content should be omitted, while important content should be distilled and summarized, with proper indexing so it can be quickly recalled and used when needed.

## Long-Term Memory Creation Workflow

### Daily Memory

1. Create the current day's memory document at the **top level of `mems/`**, named in the format `yyyy-mm-dd.md`.
2. Summarize and organize the day's conversation history and write it into the memory document.

> **Hard Rule:** During daily memory creation, **always write only to the top level of `mems/`**. It is **strictly forbidden** to create or use any period directories (`WeekN/`, `mm/`, `seasonN/`, `yyyy/`) during this step.
>
> Period directories are **only created by their corresponding period summarization steps** — for example, `WeekN/` is only created when performing **weekly memory** (every Sunday = the last day of the week, during sleep time).
>
> In other words: Monday through Saturday daily memories are all placed flat at the top level of `mems/`. Only on Sunday night, after completing the weekly memory, are the 7 daily documents of the current week moved into the newly created `WeekN/`.
>
> **Common mistake:** Seeing "Today is Monday, it belongs to Week 2" and immediately creating `Week2/` to write into it — this is **wrong**. `Week2/` must wait until Sunday of that week to be created.

> **Hard Rule:** `mems/` is exclusively the product of **sleep time**.
>
> - It is **strictly forbidden** to create or write to `mems/yyyy-mm-dd.md` outside of sleep time (including cases like "generating in advance" or "writing today's memory in the morning").
> - Daily memory documents can only be generated by this workflow during **the day's sleep time**. Before generating, confirm that the day's document **does not already exist**. If it does, it **must be overwritten** with a complete version based on the full day's conversation history — **do not skip**.
> - When the user says "remember this" mid-conversation: **directly rely on the day's conversation history** (it will naturally precipitate during the night's sleep time). **Do not** create a memory document early because of this. If temporary note-taking is truly needed, write to a temporary location **outside** `mems/` (e.g., `.pi/pending-<date>.md`).
> - **Common mistake:** The user says "remember today's stuff" in the morning, and someone manually creates `mems/2026-09-10.md` — this is **wrong**.

### Higher-Level Memory

If multiple memory creations need to occur on the same day, the order is: **Daily Memory → Weekly Memory → Monthly Memory → Quarterly Memory → Yearly Memory**. Lower-level memories must be completed before proceeding to higher-level ones.

Higher-level memories should only reference the subordinate memory documents from that period. It is **forbidden** to go back and read the original daily conversation records, and **forbidden** to skip levels. For example:

- **Weekly memory** only references the 7 daily `yyyy-mm-dd.md` files of the current week (Monday–Sunday).
- **Monthly memory** only references the weekly `mem.md` files from the current month. Weeks that have not yet ended during the monthly memory process are excluded and counted toward the next month. Skipping levels to read daily `yyyy-mm-dd.md` files is **forbidden**.
- **Quarterly memory** only references the monthly `mem.md` files from the 3 months of the current quarter. Skipping levels to read daily `yyyy-mm-dd.md` or weekly `mem.md` files is **forbidden**.
- **Yearly memory** only references the quarterly `mem.md` files from the 4 quarters of the current year. Skipping levels to read daily `yyyy-mm-dd.md`, weekly `mem.md`, or monthly `mem.md` files is **forbidden**.

The higher-level memory workflow is as follows:

1. **Execute only at the end of the respective period** (Weekly = every Sunday; Monthly = last day of the month; Quarterly = last day of the quarter; Yearly = December 31st of the year, all during sleep time). Create the corresponding period directory (`WeekN/`, `mm/`, `seasonN/`, `yyyy/`) inside `mems/`.
2. Create a `mem.md` document in the corresponding period directory. Following the rules above, read the subordinate memory documents and compose the memory content for that period.
3. Move the subordinate documents/directories from that period into the period directory.

> **Tip:** Period directories are storage boxes that are only "sealed shut" during end-of-period review. While the period is ongoing, subordinate documents should remain flat at the upper level — **do not pack them away early**.
